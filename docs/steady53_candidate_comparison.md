## 4. 已坐实的整机转速矛盾

只读 Simulink API 给出：

```text
final_steady_24a/TAC/Constant                  Value = 66100
final_steady_24a/TAC/Compressor/Gain1          Gain  = 1/55090
final_steady_24a/TAC/Compressor/Gain2          Gain  = 1/55090
```

因此压气机两个查表的实际归一化转速恒为：

```text
66100 / 55090 = 1.19985478308223
```

- ✅ 当前压气机域为 `[0.9, 1.1]`；C0 的 729 个记录点全部高于上限。
- ✅ 候选压气机域为 `[0.4, 1.1]`；C1/C3 的全部记录点均高于上限。
- ✅ 当前透平速度域上限为 `66107.74 rpm`，所以 C0/C1 的透平没有越界。
- ✅ 候选透平速度域为 `[22036, 60599] rpm`；C2/C3 的全部记录点均以 `66100 rpm` 越界。
- ✅ 压气机查表块的外推方式为 `Clip`。这意味着模型虽能跑到 500 s，却实际上一直使用速度上边界，而不是在论文设计转速线上计算。

这条证据能够直接解释“模型能跑通但曲线和论文明显不同”的一部分原因：正式模型同时保存了 `66100 rpm` 运行输入和 `55090 rpm` 归一化基准，造成约 20% 的转速口径冲突和静默查表截断。⚠️ 它是已经证实的根因之一，但本轮不能据此声称它是所有温度、压力和功率偏差的唯一根因。

## 5. Gate 决定与下一步

根据已批准规则，查表越界属于硬失败，所以：

- ❌ `eligible_for_14000=false`；没有 winner。
