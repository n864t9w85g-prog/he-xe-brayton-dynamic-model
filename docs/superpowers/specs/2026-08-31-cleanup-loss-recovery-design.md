## 2. 根因与设计修正

### 2.1 直接原因

误清理删除了工作区文件和 `.gitignore` 覆盖的临时目录内容，但没有删除关键本地 Git 对象。

### 2.2 暴露出的流程缺陷

A1 不可变来源合同把关键稳态快照固定在：

```text
tmp/steady53_curves_20260828/source_f8bcd83/final_steady_24a.slx
```

这个路径同时具有两个相互冲突的身份：

1. 它是后续所有候选的不可变科学基线；
2. 它位于默认可清理、默认不进入 Git 的临时目录。

因此原 SHA256 合同能够发现缺失，却不能独立恢复缺失。方案 A 的核心修正是把“权威源”和“可再生产物”分开：

- 权威源进入 Git 跟踪的 `data/provenance/baselines/`；
- `tmp/` 只保存可从权威源重新生成的运行副本和结果；
- 历史保护清单原样保留，作为事故前状态证据，不覆写成新口径。

## 3. 目标目录与身份

恢复后新增以下 Git 跟踪资产：

```text
data/provenance/baselines/f8bcd83/
├── final_steady_24a.slx
├── final_dynamic_24a.slx
├── baseline_manifest.csv
└── README.md
```

身份规则：

- `final_steady_24a.slx` 是 A1 临时候选唯一允许读取的权威源；
- `final_dynamic_24a.slx` 只作为事故恢复与历史溯源资产，不恢复其旧参数结论的可信状态；
- 两份文件的内容必须来自副本仓库 `f8bcd83` 的 Git blob，不从当前根目录模型复制；
- `baseline_manifest.csv` 记录来源仓库、来源提交、Git 路径、字节数、SHA256、恢复日期和用途；
- `README.md` 明示“内容身份恢复”不等于“历史动态结论恢复”。

两份 SLX 分别约 617 kB 和 660 kB，使用普通 Git 跟踪；本阶段不引入 Git LFS 或新的外部存储依赖。

## 4. 恢复架构

```text
本地副本 Git 对象库
commit f8bcd83
        │  git cat-file 导出
        ▼
隔离临时文件
        │  SHA256 硬门
        ▼
data/provenance/baselines/f8bcd83/
        │
        ├─ A1 合同只读引用
        │
        └─ 必要时重建 tmp 兼容快照
              仅作历史清单复核/运行副本
```

恢复过程不得通过解包或直接编辑 SLX/XML 改变内容。正式的 Simulink 结构修改仍只能由后续获批任务通过 MATLAB/Simulink 官方 API 作用于独立临时副本。

## 5. 恢复阶段与停止门

### R0：灾后状态封存

1. 记录两个仓库的提交、分支、工作树状态和对象完整性结果；

3. 建立灾后恢复分支或提交，不混入正式模型行为修改；
4. 不删除现有未跟踪文件。

停止门：若封存动作会覆盖现有修改或无法唯一识别目标文件，停止并报告。

### R1：精确恢复与双重哈希核验

1. 从副本仓库提交 `f8bcd83` 导出两个 SLX blob；
2. 导出后先在隔离路径计算 SHA256；

4. 写入基线清单和用途说明；
5. 重新核验 Git blob 内容、工作树文件和清单三者一致。

停止门：任何字节数或 SHA256 不一致，都不得改写 A1 合同，也不得启动后续实验。

### R2：合同迁移与历史清单闭合

3. 增加从权威源重建旧 `tmp/source_f8bcd83/` 快照的显式恢复工具或测试夹具；
4. 使用重建副本复核事故前 `protected_after.csv` 达到 34/34；

停止门：不得为了让旧清单通过而修改旧清单中的路径或哈希。

### R3：Task 3 恢复

5. 代码审查通过后形成单独提交。

停止门：不得删除或弱化失败测试来制造通过结果。
