# 后续执行计划（只读审计后的建议）

本计划不是修复授权，也不改变论文、验收标准或交付边界。每一阶段都必须先保留当前基线，并在 `tests/` 或 `tmp/` 探索区完成独立验证；未经过人工确认的物理机制不得进入 `final_dynamic_24a.slx`。

## 阶段 0：基线与证据封存

目标：建立可重现的输入、版本、哈希和失败日志。

验证：重新核对 `final_dynamic_24a.slx`、活动 MAT、入口脚本和论文 PDF 的 SHA-256；保存不改模型的 MATLAB/Simulink 环境、solver、StopTime、错误块和时间；确认 Step 0 备份命名是否满足正式规则。若备份状态无法确认，列为人工确认项，不自行覆盖任何文件。

## 阶段 1：压气机域越界的最小可证伪实验

目标：在探索区复现 `FlowBelowMaximum_Assertion` 的 corrected-flow 轨迹，区分压气机表域问题、上游热力状态问题和代数环/初始化问题。

验证：使用当前活动表和只读模型副本/离线函数，记录 `m_ratio`、修正转速、压力比、入口状态和上界比较；不禁用 Assertion、不改正式表、不改变求解器。实验输出只回答“越界发生在哪里、由哪个输入驱动”，不以曲线接近论文作为正确性判据。

## 阶段 2：单一表 5.2 设计点稳态基线

目标：在探索区建立无负荷/无反应性扰动的单一设计点检查，核对表 5.2 的 `0.658 MPa -> 1.551 MPa`、温度、质量流量、TAC 功率平衡和转速稳态。

验证：分别检查静态方程残差、查表域覆盖和闭环动态稳定性；两者必须分开报告。候选表的 activation gate 与 `start.m` 实际加载行为必须先澄清。

## 阶段 3：论文 §5.4.1 六阶段启动场景映射

目标：只用已有开环输入端口和论文规定的时序，构造可审计的启动场景描述；不向模型添加调度器或控制器。

验证：逐阶段核对初值、锂流量、TAC 启动判据、StopTime、功率/温度/转速输出和验收阈值。若当前模型缺少必要的开环端口或初值，先报告缺口并请求人工决策，不用补丁替代物理机制。

## 阶段 4：§5.4.2 变工况逐场景验证

顺序：稳定点 ±5% 转速、TAC 负荷扰动、反应性扰动。每个场景单独运行、单独保存结果和误差表；优先使用已有 `rho_fw`、`Pload_fw` 和转子初值端口，不改拓扑。

验证：按 `验收标准_论文5.4.md` 的峰值、稳态、时间和曲线形状逐项比较；对论文内部矛盾（如 TAC 功率 1009/1099）保留原文和验收文件的标记，不自行改阈值。

## 阶段 5：交付边界和依赖审计

目标：逐块审查 Assertion、Scope、Display、To Workspace、Unit Delay、`alphac` 及所有反馈方向，形成“允许/待确认/不允许”清单。

验证：确认没有外挂 PID、传感器滤波、安全联锁、状态回注、外部电力系统、神经网络或拟合补丁；确认正式模型不依赖 `tests/`、`tmp/`、`.bak`、候选输出或调试脚本。对论文物理耦合（转子动力学、温度负反馈）不得误判为控制器。

## 阶段 6：人工确认门与正式修改（尚未授权）

以下事项在现有证据下必须人工确认：是否保留/删除 `alphac`；Unit Delay 是否为论文允许的数值实现；两区离散和 Assertion/记录块是否属于正式交付；候选压气机表何时满足激活门禁；Step 0 备份是否有效。只有确认后，才能依照“记录基线 -> 最小修改 -> 重跑 -> 对比 -> 检查副作用 -> 记录出处”的协议进行正式修改。

## 下一阶段唯一优先事项

先完成阶段 1 和阶段 2：在不改正式模型的探索区，追踪 4.43696 s corrected-flow 越界，并建立单一表 5.2 设计点稳态 baseline。当前不建议直接进行动态曲线拟合或修改验收标准。
